# 次のプロジェクト: Claude Code / AI CLI のためのターミナル（構想）

filer が落ち着いたら始める。持ち主の合図で着手する（2026-10-04 に構想を記録）。
cmux（Mac 専用）のような「複数の Claude Code を並べて、どれが手を待っているか一目で分かる」ターミナルを、
Windows を第一に、macOS / Linux（x86_64 / ARM64）でも動く形で作る。

## filer から持っていくもの

filer のターミナルペインは、実機で叩かれながら一番難しい所を作ってきた。新しいターミナルはこれを土台にする。

| 部分 | 今の場所 | 中身 |
| --- | --- | --- |
| PTY とシェル | `src/terminal.rs`（約 2,200 行） | `alacritty_terminal` の上の `Terminal`。ConPTY（新しい版を同梱、`scripts/fetch-conpty.ps1`）、既定のシェル選び（pwsh / 5.1 / ログインシェル）、`FILER_PTY_LOG` |
| キー入力の変換 | 同上の `win32_key` / `special_record` / `char_record` | win32-input-mode（キーを Windows の生の入力として渡す。Q27）、和音、`<C-c>` などの制御文字 |
| ターミナルからの通知 | 同上の `scan_osc7` ほか | OSC 7（シェルの現在地。29 節）、ブラケットペースト、問い合わせへの応答 |
| マウス | 同上 | ホイールのマウス報告（Q28）、ドラッグでの選択、スクロールバック |
| 描画 | `src/ui/term.rs`（約 430 行） | egui での文字の格子、カーソル、選択、検索の色 |
| シェルの連携 | `src/shellhook.rs` | `filer shell-hook pwsh / bash / zsh` が出すシェルの設定 |
| GPU のバックエンド | `src/main.rs` の `wgpu_options` / `pick_backends` | Windows は GL を先に試す（AMD のドライバが Vulkan / DX12 で何もしない窓に 1 コアを使う件。47 節、Q70） |
| DLL の読み込み制限 | `src/main.rs` の `restrict_dll_search` | exe の隣と System32 からしか DLL を読まない（#184） |
| 試験の仕組み | `src/keyscript.rs`、`scripts/xrun.sh`、`.claude/*-role.md` | `--keys`・`<State:>`・`<Shot:>`・`<Quit>`、Xvfb の Linux レーン、2 台の実機レーン、毎時のマージ |

## 先にやること: ペインを独立したクレートに切り出す

**v0.78.125 で済んだ**（2026-10-05）。クレートは uchmk/tsumugi の `crates/tsumugi-pane`（v0.93.10 からは uchmk/ito の `crates/ito-pane`）、経緯は tsumugi の `docs/pane-extraction.md`。下は着手前に書いた構想。

filer の中にあるうちに、ペインの部分をクレート（たとえば `filer-term`）に分ける。filer はそれを使う側の 1 つになり、
新しいターミナルはもう 1 つの使う側になる。ペインに入れた直しが両方に効く。

切り出すときの約束（CLAUDE.md の「マルチ OS 対応」「マルチアーキテクチャ対応」をそのまま当てる）:

- **OS ごとの処理を 1 か所に閉じ込める。** ConPTY、win32-input-mode、DLL の制限は `#[cfg(windows)]` のモジュールに、
  Unix の PTY は `#[cfg(unix)]` に。使う側（filer や新しいターミナル）から OS の違いが見えない API にする。
- **描画とロジックを分ける。** PTY・キー変換・OSC の解釈は egui に依らない層に置き、egui で描く部分は別の層にする。
  別の描画の仕組みに載せ替えるときも、下の層はそのまま使える。
- **Pure Rust を優先する。** C のライブラリを抱えるクレートは避け、6 ターゲット（Windows / macOS / Linux × x86_64 / ARM64）へのクロスコンパイルを軽く保つ
  （Lua を入れない理由と同じ。CLAUDE.md の「設計の約束事」）。
- **修飾キーを抽象化する。** macOS の Cmd と Windows / Linux の Ctrl を差し替えられる形にしておく。
- **今のテストを一緒に持っていく。** `terminal.rs` のテストと、ペインの実機の行（TESTING.md の 1、19、29、40 節）が、切り出しで壊れていないことの証拠になる。

filer 側の作業も増える（API の境目を引き、filer の呼び出しを直し、CI に新しいクレートを足す）。
切り出しは新しいターミナルを始める直前に、filer のリポジトリの中でやるのがよい。

## 画面の分割（レイアウト）も共有のクレートにする

ここでいう「ペイン」は、`<C-t>` で開くターミナルの欄（シェル 1 つ）のこと。filer の親・今・プレビューの 3 列の並びとは別物で、
ペインを切り出しても分割の自由度は変わらない。ペインのクレートは「1 つの四角の中に 1 つのシェルを描く」部品で、四角をいくつ、どう並べるかは使う側が決める。
（2026-10-04、持ち主との会話で整理した）

- **いろいろな分割には、別にレイアウトの仕組みが要る。** tmux や WezTerm のように、縦横の分割を木の形で持ち、四角ごとに中身（ターミナル、一覧、プレビューなど）を
  1 つ置き、境目をドラッグで動かし、キーで四角の間を移動する。新しいターミナルには必須（Claude Code を何本も並べるのが目的）。
- **今の filer の並びは決め打ち。** 3 列（親・今・プレビュー）、2 分割（左右に一覧。Q2）、下のターミナルのペイン 1 つ。
- **レイアウトも独立したクレートにする。** 中身の種類を知らない作りにして（四角に何を描くかは使う側が渡す）、ターミナルのペインと同じく filer と新しいターミナルで共有する。
  filer に入れば、一覧を 3 つ並べる、ターミナルを横に置く、ターミナルを 2 つ開く、といった並びが選べるようになる。
- **順番: 新しいターミナルで先に作り、実機で揉んでから filer に持ち帰る。** filer の今の並びには実機の試験（2 分割の 38 節、ペインの 1・19 節など）が積み上がっていて、
  先に filer で作り替えるとそれをやり直すことになる。新しいターミナルで出来がよいと分かってから入れる。
- 移植しやすさの約束はペインのクレートと同じ（OS の処理を `cfg` に閉じ込める、Pure Rust、描画とロジックを分ける、修飾キーの抽象化）。

## 欲しい機能（持ち主の構想、2026-10-04）

### 1. Claude Code / AI CLI に特化した UI / UX

- **入力欄を分ける**: 複数行のプロンプトやコードブロックを書くとき、普通の TUI の `Shift+Enter` 問題を起こさずに編集できる専用の入力欄を持つ。
- **ストリーミングと TUI の描画の最適化**: Claude Code の進み具合の表示や差分（Diff）の描画で、画面が崩れたりちらついたりしないように描画を作り込む。
- **履歴とコンテキストの見える化**: 送ったプロンプト、生成されたトークン数、応答にかかった時間を、横のパネルなどで一目で見て管理できるようにする。

### 2. 複数のセッションとワークスペースの統合

- **複数のエージェントを並べて表示**: Claude Code を何本も立ち上げたとき、それぞれの状態（実行中・入力待ち・エラーなど）を、タブやペインの状態アイコンで見せる。
- **コンテキストの自動切り替え**: フォルダの移動や Git のブランチの切り替えに合わせて、関係する環境変数や設定を自動で切り替える。

### 3. 部品化・軽さ・設定のコード化

- **とても軽く、すぐ起動する**: Rust で書き、WezTerm や Alacritty の水準の描画の速さと、少ないメモリを目指す。
- **宣言的な設定**: 込み入ったキーの割り当てやプロファイルを、1 つの設定ファイル（Lua、TOML、KDL など）で管理し、共有できるようにする。
  Lua にするなら、filer で Lua を入れなかった理由（C の Lua をビルドに抱える）とどう折り合うかを先に決める。

### 4. マルチモーダルなコンテキストの統合

- **クリップボードと画像をそのまま渡す**: スクリーンショットや画像ファイルを、ドラッグ＆ドロップか `Ctrl+V` でターミナルに置くだけで、
  Claude Code などの AI CLI が読めるパスや Base64 の形に変換して添付する。
- **画面のキャプチャを自動で返す**: Web アプリを作るとき、ブラウザの描画結果や崩れた UI のキャプチャをターミナル側から取り、
  プロンプトのコンテキストとしてそのまま AI に渡せるようにする。
- **音声の入力と通知**: 長いプロンプトを音声で入力する。Claude Code の作業の完了やエラーを、音声や効果音で知らせる。

## 最初に作る範囲の案（2026-10-04 の会話から）

欲しい機能は広いので、最初は「Claude Code を並べるための道具」に絞る。汎用のターミナルとして Windows Terminal を超えようとすると終わりがない。

1. 左の縦タブにセッションを並べる。
2. 各タブに、作業フォルダ、Claude Code が窓のタイトルに出す作業名、状態（動いている / 入力待ち / 終わった）を出す。
3. 入力待ちになったタブに通知の印を付ける。Claude Code のフック（`Notification` / `Stop`）からターミナルへ印を送る形が素直。
4. ペインの分割と、セッションの保存・復元。

始めるときは、別のリポジトリを作り、範囲と最初の版の線引きを QUESTIONS.md のような形で決めてからにする。

## 参考にしたもの（2026-10-04 の調べ）

- cmux: Mac 専用。縦のサイドバーと通知の印で、複数のセッションを並べる。
- Warp: 縦タブに Claude Code のアイコンと状態のバッジ、未読の印が出る（Windows 版あり）。
- WezTerm: 公式は上下のタブだけ。縦タブは非公式の分岐版（本家の PR #7574）。横に Claude Code のセッションをカードで並べる部品（Agent Cards）がある。
- Rio / Alacritty: 縦タブもセッションの状態も無い。
