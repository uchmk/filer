# filer — 確認事項（QUESTIONS.md）の書き方と多数決

CLAUDE.md から分けた（2026-10-07）。QUESTIONS.md に質問を書く・回答を反映する・票を数えるときに読む。

人の判断が要るときは、作業を止めて QUESTIONS.md に質問を書く。自動実行モードでも、対話中でも同じ。TODO.md には、どのタスクがどの質問で止まっているかだけを書く。

- **質問の書き方**: QUESTIONS.md の末尾に、下の形式で追記する。
  - 番号は通し番号で、再利用しない。
  - 選択肢には必ず推奨を 1 つ付ける。
  - 回答が来なくても推奨で進めてよい軽い事項なら、そう書き添える。
- **TODO.md への印**: 該当タスクの末尾に `（要確認: Q7）` と付ける。
- **回答の反映**
  1. 人は、質問の「回答」欄に書き込む。
  2. 回答が書かれていたら、その内容でタスクを進める。
  3. 進めたら、状態を `反映済み` にし、TODO.md の `（要確認: Qn）` を外す。
  4. 回答があいまいなら、同じ質問に追記して聞き直す（状態は `未回答` に戻す）。

### 多数決で進める質問（2026-10-02、持ち主の指示）

持ち主の回答を待たずに、**クラウド（質問を書いた側）・Windows x64・ARM64 の 3 票の多数決**で決めてよい質問がある。
持ち主が「回答」欄に書けば、いつでもそちらが優先する（多数決で入ったものを取り消すことも含む）。

- **対象は、技術的に正解を論じられる質問と、既定のキー割り当て・既定の動き**（後者は 2026-10-04、持ち主の指示）。次は対象にせず、これまでどおり持ち主を待つ:
  見た目、外に影響するもの（依存クレートの追加、リリース、workflow、セキュリティ）、
  持ち主の機械に関わるもの（ソフトを入れるかなど）。迷ったら対象にしない。
- **出し方**: 状態を `投票中` にし、選択肢に「（推奨）」を付けない（推奨に票が引きずられる）。代わりに `- 投票:` 欄を置き、
  書いた側が自分の票を理由付きで 1 行書く。形は下の例。
- **票の入れ方**: Windows の 2 レーンは、毎回の実行で `投票中` の質問に票を入れる（`windows-role.md` の「Votes」）。
  票は各自の報告に書き、マージする側が QUESTIONS.md の `投票` 欄に写す（実機の PR が QUESTIONS.md を触ると、
  ここを頻繁に書き換える本流と衝突するため）。**実機で見たことに根拠の無い票は数えない**（同じ系統のモデルが
  同じ前提から 3 票そろえても、独立した 3 票にはならない。実機の票の値打ちは、実機で見たことにある）。
- **数え方**（マージする側が毎回やる。`merge-role.md` の 0）:
  - 同じ選択肢に 2 票揃ったら `- 多数決:` 欄に選択肢と揃った日を書き、**その場で**状態を `多数決で決定` にし、TODO.md の
    `（要確認: Qn）` を外す（2026-10-03、持ち主の指示。それまでは 24 時間、持ち主の回答を待っていた）。
    あとから持ち主が回答すれば、そちらが優先する。
  - 3 票が 1-1-1 に割れたら、状態を `未回答` に戻し、持ち主を待つ。「持ち主が決めるべき」という票は、どの選択肢にも数えない。
- **進める**: `多数決で決定` は回答済みと同じに扱う（自動実行モードの「回答済みの質問を優先」も含む）。
  反映したら状態を `反映済み（多数決）` にする。CHANGELOG にも「Q57、多数決」のように書く。
