```

s1: toast: $ echo hello >out.txt (no path: the line has a shell operator; use %* to place it)
s2: launched: 38068 echo a;b "C:\…\w3220\a.txt"
s2: toast: $ echo a;b "C:\…\w3220\a.txt"
```

`done.txt` は `quit: yes` / `keys: done`。ファイル: `out.txt` = `68 65 6C 6C 6F 20 0D 0A`（`hello ` と改行、パス無し）、`o.txt` = `61 20 0D 0A`。

- `>` の 2 行はパス無しで注記付き、`%*` の行はパスが入って注記無し。行の残りも変わらず。

## Q86 のために押したもの（`<S-Enter>` のカーソルの始まり）

`yazi.toml` の `[opener] mine` を `no-such-tool %s`（"Missing tool"）→ `cmd /c rem %s`（"Cmd rem"）の順にし、`*.txt` に当てた
（`YAZI_CONFIG_HOME` は空のフォルダ。証拠は `C:\dev\filer-evidence\arm-retests-55\q86\`）。`a.txt` の上で:

| キー | 結果 |
| --- | --- |
| `<S-Enter><Enter><Wait:2000>` | `pick: Missing tool (not found) (no-such-tool %s) \| Cmd rem (cmd /c rem %s)`、押すと `toast: Open failed: \`no-such-tool\` was not found — …` |
| `<S-Enter>j` | `j` は一覧を動かさず絞り込みに入る: `pick:` が空になり、`toast: Nothing matches \`j\` — <Esc> closes` |
| `<S-Enter><Down><Enter>` | `launched: … cmd /c rem "…\a.txt"`（2 行目に行くには `<Down>` が要る） |
| `<Enter><Wait:2000>`（`<S-Enter>` なし） | これも `Open failed: \`no-such-tool\` was not found` |

## 所見

1. **`launched:` が、起動に失敗したオープナーにも PID 付きで出る。**上の `<S-Enter><Enter>` と `<Enter>` の `<State:>` は
   `launched: 29200 no-such-tool "…\a.txt"` と書き、2 秒後のトーストは `Open failed: \`no-such-tool\` was not found`。`<Wait:>` を入れない
   `<State:>`（r1、r3）は `launched:` と `$ no-such-tool …` のトーストだけで、失敗がまだ見えない。`<State:>` を読むスクリプトは、
   `launched:` を「起動した」の印として読めない（PID は間に入る `cmd` か何かのもの）。報告にとどめる。

### Proposals

1. **既定の `<Enter>`（`open`）も、入っていないオープナーを飛ばして最初に入っているものを使うべき。**
   - 何に当たったか: Q86 の probe の最後の行。`<S-Enter>` を通さない `<Enter>` も、`[opener]` の 1 行目が無いプログラムだと毎回 `Open failed: … was not found` になる。
     `<S-Enter>` の一覧はもう `(not found)` を知っているのに、`<Enter>` はその知識を使わない。
   - どう変えるか: `open` のときも、`(not found)` と判定したオープナーを飛ばして次を使う。全部無ければ今の失敗のトースト。飛ばしたときはトーストに
     `(skipped no-such-tool: not found)` のように 1 句足す。
   - なぜ: Q86 で `<S-Enter>` だけを直しても、一番押す `<Enter>` が同じ共有 `yazi.toml` で失敗し続ける。
   - 大きさ: 関数 1 つ（`which` の結果はもう `<S-Enter>` の一覧で引いている）。既定の動きなので、採るなら投票。
2. **`<State:>` の `launched:` は、失敗した起動では `failed:` か何か別の行にしてほしい。**
   - 何に当たったか: 所見 1。
   - どう変えるか: 失敗が分かった時点で `launched:` を `launch failed: no-such-tool …` に置き換える。
   - なぜ: 実機のレーンは `launched:` を起動の証拠にしてきた（32.20 など）。失敗も同じ行に出るなら、`toast:` まで読まないと区別できない。
   - 大きさ: 1 行〜関数 1 つ。
