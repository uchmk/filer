### Proposals（2 件）

#### 提案 1: 関連付けの無いファイルの `<Enter>` は「既定のアプリで開いた」と言わない

- **踏んだこと**: `.xyz`（`assoc .xyz` は `File association not found`）で `<Enter>`。トーストは `Opened thing.xyz with the system's default app` だったが、
  実際に出たのは Windows の「このファイルを開く方法」の窓（`OpenWith.exe`）で、既定のアプリは無い。ファイルは何にも開かれていない。
- **どう変えるべきか**: Windows では開く前に `AssocQueryStringW(ASSOCSTR_EXECUTABLE)` で関連付けがあるかを見て、無ければ
  `No app is set for .xyz; Windows asked which one to use` のように言う（`ShellExecuteExW` の結果は変えずに、言い方だけ分ける）。
- **なぜ**: いまの文は「開いた」と言うので、窓が後ろに出たときに利用者は開いたものを探す。#217 の「開かなくても成功と言う」と同じ型の、最後に残った形。
- **大きさ**: 関数 1 つ（Windows だけ。他の OS は今のまま）。

#### 提案 2: `FILER_KEYS_DONE` に、最後に OS へ渡した URL / パスを書く（例 `opened: https://github.com/…/issues/new?…`）

- **踏んだこと**: `<F12>` が何を埋めたか（版と OS の欄）を確かめたかったが、filer から読めるのはトーストだけで、URL はブラウザにしか無い。
  Chrome の窓のタイトル `New issue - Google Chrome` で「フォームが開いた」までは言えたが、欄の中身は読めなかった。しかも試すたびに持ち主の Chrome に
  タブが 1 枚増える（この回で 2 枚。送信はしていない）。
- **どう変えるべきか**: `open_url` / `open_default` に渡したものを状態に残し、状態ファイルに `opened:` の行で書く。
- **なぜ**: 26.1 / 26.3 / 26.4（URL の中身）が文字で読めるようになり、Q64 で欄を増やしたときにもそのまま測れる。
- **大きさ**: 数行。
