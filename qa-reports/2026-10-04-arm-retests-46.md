## Findings

### 1.（所見）弾かれた `[ui] backend` の「既定」は `auto` の既定ではない — Windows では GL に戻らない

同じ機械・同じビルドで:

- `backend` 無し（`auto`）→ `Adapter … (Gl, Other)`、`last-run.toml` の `backend = "Gl"`
- `backend = "directx"`（名前が不正）→ `Adapter … (Vulkan, IntegratedGpu)`、`backend = "Vulkan"`
- `backend = "metal"`（この OS に無い）→ 同じく `Vulkan`

コードもそのとおりで、`src/main.rs` の `wgpu_options` は、名前を弾いた枝（`Err(_) => return options`、1179 行）と
アダプタが無い枝（1182-1186 行）で**既定の `WgpuConfiguration` をそのまま返す**。`auto` の枝（1170-1177 行）だけが
Windows で `Backends::GL` に絞る。つまり「drawing with the default」の *default* が 2 通りある。

ARM64 では実害が見えない（上の 47.1 のとおり Vulkan でも 0.000 s）。**効くのは x64 の AMD の機械**で、
そこでは Vulkan / DX12 が 10 秒で 10.0 CPU 秒（#232、#240）。v0.75.0 は「Windows の既定を GL にする」変更なのに、
`filer.toml` の打ち間違い 1 つで**その変更の前に戻り、しかもトーストは「既定で描く」としか言わない**。
直し方は小さい（弾いた 2 つの枝からも `auto_backends` を通す）が、動きが変わるので報告に留める。

### 2.（行の文言）TESTING.md 47.7 の「`Adapter` は Vulkan か DX12」は v0.75.0 で古くなった

47.7 は v0.74.0 に書かれた行で、当時は既定が wgpu の選択だった。v0.75.0 で Windows の既定が GL になったので、
この括弧は「既定」ではなく「弾かれたときの戻り先」を述べていることになる。今回はたまたま文言どおり
（Vulkan）だったが、所見 1 を直せば GL になり、**同じ文のまま結果が逆になる**。
行の書き換えは報告に回す（こちらでは直していない）。

## Proposals（3）

1. **弾いた `[ui] backend` も `auto` と同じ道に落とす。**
   - 何があったか: `backend = "directx"` の 1 文字の打ち間違いで、この機械は Vulkan で描いた（上の所見 1）。
     x64 の AMD なら、それは idle で 1 コアを食う構成に戻ること。
   - 変えるもの: `wgpu_options` の `Err(_)` の枝と「アダプタが無い」の枝で、`options` をそのまま返さず
     `auto_backends(cfg!(windows), …)` を通す。つまり「既定で描く」を 1 つの意味にする。
   - なぜ: 設定の打ち間違いが性能の退行を連れてくるのは、誰も結び付けられない。`auto` と同じ絵を出すのが
     「既定」の素直な読み。
   - 大きさ: 数行（枝を 1 つの関数にまとめる）。
2. **警告に、戻り先の名前を書く。**
   - 何があったか: トーストも `filer env` も `drawing with the default` で止まる。この run では、
     どの backend で描いたかを知るために 4 つの `FILER_STATE_HOME` を用意して `last-run.toml` を読んだ。
   - 変えるもの: 警告を `drawing with Gl instead`（実際に選ばれたもの）にする。選ぶのは窓を開いたあとなので、
     設定を読む時点の文には入らない — トースト側（窓が開いたあと）で 1 回だけ言い直すのが素直。
   - なぜ: 「既定」が 2 通りある（所見 1）以上、名前を書かないと読んだ人は確かめようがない。
   - 大きさ: 1 関数。
3. **`filer env` の `Adapter` に、いつの起動のものかを常に書く。**

     版が同じだとこの行は出ない。つまり「さっきの起動のものか、3 日前のものか」が読めない。

   - なぜ: バグ報告に貼られた `filer env` の `Adapter` が、報告された起動のものだとは限らない。
     1 行あれば読む側が判断できる。
