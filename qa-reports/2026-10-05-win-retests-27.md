## Findings

1. **`filer env`'s `did not start:` repeats the toast whole, `Terminal failed:` included.**
   `app.rs:5158` passes the toast text (`said`) to `remember_shell_failed`, and
   `envreport.rs:316` puts `did not start: ` in front of it, so the row reads
   `did not start: Terminal failed: `nosuchshell` …`. The unit test
   (`envreport.rs:392`) feeds the bare reason, so it passes. Either store the
   reason without the `Terminal failed: ` prefix, or rewrite 1.40's last sentence;
   the row stays open until one of them lands.
2. The Windows-only `cargo test` failure above, already in TODO.md: confirmed here.

### Proposals

1. **Make the panic report's `at:` use `/` on every platform.** What I ran into: the
   one red test, which reads `at: src\keyscript.rs:514` on this machine and would read
   `src/keyscript.rs` on Linux. What should change: `panic_report` writes
   `location.file().replace('\\', "/")`. Why: a script or a person comparing
   `<name>.panic` files from the two lanes would see one place, and the test stops
   depending on which machine runs it, which `scripts/verify.sh` cannot catch (it runs the tests on
   Linux only). Size: a line.
2. **Drop the system's sentence once filer already knows the shell is missing.**
   What I ran into: the toast and `filer env` both end
   `(指定されたファイルが見つかりません。 (os error 2))` after already saying
   `` `nosuchshell` was not found on PATH ``. What should change: when
   `util::locate` found nothing (the first arm at `app.rs:5155`), leave out `({e})`.
   Why: it says the same thing twice, the second time in the system's language;
   v0.78.29 removed the same kind of sentence from spot's `Resolves` for that reason.
   This also shortens the line a person reads in finding 1. Size: a line.
3. **Let 1.41's second sentence be read from the PTY log.** What I ran into: the
   only bubbletea program here signs in to the owner's GitHub, so an unattended run
   cannot start it, and "starts at once instead of pausing" is a look. What should
   change: the row says the `in reply` line follows its `out` query within, say,
   50 ms (here 0 and 2 ms), and keeps `gh dash` as an optional check for a person.
   Why: as written, the row's second half can only be settled by the owner, or by a run
   that has their leave. Size: a row rewrite.
