### 画面の倍率を 150% にした方法と、戻したこと

この機械の内蔵パネルは **100%**（filer の `Window: 1360 x 860 px (1360 x 860 pt @ 1)`）で、行は「倍率 100% 以外の画面でも」を見ろと言う。
`SystemParametersInfoW(SPI_SETLOGICALDPIOVERRIDE=0x009F, 2, 0, 1)` で**推奨から 2 段上**（= 150%）にした。即時に効き、ログオフは要らない。

- 効いたことの根拠は filer 自身: 変更後の run で `Window: 2040 x 1290 px (1360 x 860 pt @ 1.5)`、変更前と変更後の両方で `filer env` を読んだ。
  PowerShell から `GetDpiForMonitor(MDT_EFFECTIVE_DPI)` を読んでも**当てにならない**（呼ぶ側の DPI awareness に合わせた値が返るので、
  変更前が 96、戻したあとが 144 と逆の値が出た）。**倍率の正は filer の `@ N`。**
- 戻した: `SPI_SETLOGICALDPIOVERRIDE(0)`（= 推奨 = この機械では 100%）→ filer が `1360 x 860 px (… @ 1)` に戻ったのを確認 →
  API が作った `HKCU:\Control Panel\Desktop\PerMonitorSettings\ENC3148…` のキーを削除 → レジストリは run の前と同じ
  （`SDC420D0…` の `DpiValue = 4294967294` だけ）→ もう一度 filer を起動して `@ 1` を確認。**持ち主の画面設定は run の前の状態に戻っている。**

### 見つけたこと

1. 不具合は無い。v0.73.62 の 2 つの変更（SVG の `<A-1>` は論理ピクセル、ラスターの `<A-1>` は物理ピクセル）は、
   倍率 150% の実機で数字どおりに出ている。
2. 覚え書き: `FILER_KEYS_DONE` の `zoom:` は `shown_scale` を通った値なので、ラスターでも SVG でも 1:1 のとき `100%` と出る。
   **倍率の違う画面でも同じ 1 行で確かめられる**ので、この 2 行の再テストは今後 `zoom:` + `<Shot:>` の 2 つだけで足りる。
3. 覚え書き: filer 自身の `scale`（`<C-=>`）は egui の zoom factor なので、**画面の倍率に掛け算で乗る**。
   150% の画面で `<C-=>` を 5 回押した run は `@ 2.25`（`probe.done` / `filer env`）だった。窓の物理サイズはほぼ変わらない（2040 → 2041 px）。

### Proposals（3 件）

#### 提案 1: `FILER_KEYS_DONE` に、その run の画面の倍率と窓の大きさを出す

- **踏んだこと**: 3.2 / 4.9 は「物理ピクセル」と「論理ピクセル」の違いを測る行なので、その run が倍率いくつで動いたかが根拠の半分になる。
  ところが倍率を読む手段が `filer env` の `Last run` しかなく、これは**ひとつ前の run**の値なので、filer を終わらせてから別のプロセスを起動して読むことになった。
  run が落ちたときや 2 本並べたときは、別の run の倍率を読むことになる。
- **どう変えるべきか**: `zoom:` の隣に `ppp: 1.5` と `window: 2040 x 1290 px (1360 x 860 pt)` の 2 行を足す。`filer env` の `Last run` と同じ値。
- **なぜ**: 倍率に依る行（3.2、4.9、将来の高 DPI の行）の証拠が、その run の 1 つのファイルで閉じる。今は証拠が 2 つのプロセスにまたがっている。
- **大きさ**: `keys_done` の書き出しに 2 行。TODO.md の「`FILER_KEYS_DONE` に、プレビューの注記…（#223 の提案 2）」と同じ場所なので、まとめて入れられる。

#### 提案 2: 画面の倍率を run の間だけ上書きする手段（`--scale 1.5`）

- **踏んだこと**: 「倍率 100% 以外の画面で」を確かめるのに、**機械全体の画面倍率を変えるしかなかった**。使ったのは文書化されていない
  `SPI_SETLOGICALDPIOVERRIDE` で、持ち主の画面設定を書き換えて戻す手順（上の節）が run のいちばん危ない部分になった。
  途中で落ちれば、持ち主のノート PC は 150% のまま残る。`<C-=>` 5 回でも `pixels_per_point` は 1.5 になるが、
  画面の倍率に**掛け算で乗る**（上の見つけたこと 3）ので「150% の画面と同じ」と言うには native の倍率を知っていなければならず、トーストも出る。
- **どう変えるべきか**: 起動時に zoom factor を決める `--scale <N>`（または `FILER_SCALE`）を足す。`App` の `scale` の初期値にして `set_zoom_factor` を呼ぶだけ。
- **なぜ**: 倍率に依る行を、**機械の設定を一切触らずに**両レーンが押せる。画面の無い Linux レーン（Xvfb は倍率 1 固定）でも 3.2 / 4.9 が押せるようになる。
  ふだん使いでも「このアプリだけ少し大きく」を毎回のキー 5 回でなく 1 回で決められる。
- **大きさ**: CLI のフラグ 1 つと起動時の 1 行、それに `--keys` と組み合わせたテスト。

#### 提案 3: プレビューの注記に下敷きを敷く

- **踏んだこと**: 1:1 の `zoom-me.png` の上に重なった注記 `3200 × 2400 · 1:1` は、格子の上に薄い灰色で描かれていて**ほぼ読めない**
  （`cap-raster-one.png`。2 倍に拡大して、何と書いてあるか知っていてようやく読めた）。暗いペインの上に出る SVG の注記（`cap-svg-one.png`）は読める。
- **どう変えるべきか**: 注記の文字列の後ろに、ペインの背景色を少し透かした角丸の板を 1 枚敷く（トーストと同じ寄せ方）。
- **なぜ**: 注記は「今どの倍率か」を人に伝える唯一の場所で、`1:1` と `107%` の区別は拡大したときほど要る。
  絵の明るさ次第で読めなくなるのは、絵を見るための表示としては逆。テストの側でも、注記が読めれば画像のハッシュでなく文字で確かめられる。
- **大きさ**: `ui/preview.rs` の注記を描く所に矩形 1 つ（数行）。
