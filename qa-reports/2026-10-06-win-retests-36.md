### Proposals

1. **Split 32.23 so the clauses that hold can be ticked.** The row has three claims:
   - the `type` sentence;
   - the named "was not found" for a missing program, which waits on Q89;
   - one toast, not two, joined without a stray space (v0.78.143 / v0.78.150).

   The first claim held on x64 in #278, #282 and this run, and #282 and this run saw the third hold too. Neither run
   could tick them, because the middle claim fails. Suggested split:
   - 32.23 for `;type nothing.txt >t.txt`;
   - 32.23a for `;nosuchprog-xyz` → `` `nosuchprog-xyz` was not found `` (Q89);
   - 32.23b for "one toast, `cmd`'s wrapped lines joined like the preview".

   Size: a TESTING.md edit and the `testcheck-ja.toml` translation.
2. **`Open failed:` is the wrong verb for a `;` line.** In k3223a nothing was opened: `type nothing.txt >t.txt` is a
   shell line with no path in it (`(no path: the line has a shell operator …)`). The toast still begins `Open failed:`,
   and `launch failed:` in the state file says the same thing better. Suggest `Command failed:` (or `Shell failed:`) for
   `:` / `;` lines, and keep `Open failed:` for openers. It costs a reader a moment each time ("open what?"), and this run
   read it twice. Size: one string, chosen where the toast is built in `exec.rs`.
3. **Support TODO.md's open item "`<State:>` shows the toasts on screen now"** (#282 proposal 3). This run again needed
   `rb.png` to confirm that the `$ …` toast was gone, because `toasts:` keeps the run's whole log. A `toasts on screen:`
   line would have made that clause a text check. No new size estimate; the TODO item already covers it.
