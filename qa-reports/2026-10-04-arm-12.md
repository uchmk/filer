## 方法

filer を押したのは `--keys` だけ。**起動は毎回 `Start-Process -Wait`** で、読みは 1 回の起動につき 1 つの
`FILER_KEYS_DONE` から取っている（理由は提案 2）。スクリプトは `q` で終わるので、どの実行も

SHA-256 付きで一覧した（`run-12-8.ps1`）。

## 結果

### 12.8 前半 — 別の改名が履歴を分岐させる（期待どおり）

`ra2<Enter><Wait:800>u<Wait:800>jrb2<Enter><Wait:800>U<Wait:800><Shot:fork-after>q`
（`r` の既定は `RenameCursor::BeforeExt` なので、`a2` は拡張子を残して語幹だけを置き換える）

```
before:  a.txt 8ED3F6AD685B   b.txt F144A6907DC4
after:   a.txt 8ED3F6AD685B   b2.txt F144A6907DC4
toasts: Renamed back to a.txt | Nothing to redo
hovered: …\fork\b2.txt    quit: yes    keys: done
```

- `a.txt` → `a2.txt`、`u` で `a.txt` に戻る（トースト `Renamed back to a.txt`、中身のハッシュも同じ）。
- `j` で `b.txt` に移って `b2.txt` に改名。
- `U` が **`Nothing to redo`** と言い、`a2.txt` は戻らない（一覧は `a.txt` と `b2.txt` の 2 件）。
  `fork-after.png` でも、一覧が `a.txt` / `b2.txt`、右上のトーストが `Nothing to redo` と `Renamed back to a.txt`、
  ヘッダが `2 items`。

### 12.8 後半 — 「新しいファイルを作っても redo は残る」は、もう成り立たない

`rc2<Enter><Wait:800>u<Wait:800>anewfile.txt<Enter><Wait:800>U<Wait:800><Shot:create-after>q`

```
before:  c.txt
after:   c.txt   newfile.txt
toasts: Renamed back to c.txt | Nothing to redo
hovered: …\create\c.txt    quit: yes    keys: done
```

行の期待は「`U` で `c2.txt` に戻る（`Renamed to c2.txt`）」だが、実際は前半と同じ **`Nothing to redo`** で、
`c.txt` は `c.txt` のまま。つまり **`a` での作成も履歴を分岐させる。**

### 12.11 の代わりに試したこと — `subst` の仮想ドライブは代用にならない

昇格なしで「ごみ箱の無いドライブ」を作れないか、`subst Z: <scratch>` を試した（12.11a の文言が
「a RAM disk or a virtual drive」なので、仮想ドライブなら同じ経路に入るかもしれない、という見込み）。

```
Z:\ で d → toast: Trashed z.txt — u to undo        (12-11-subst.txt, subst-d.png)
```

`subst` は C: のパスに解決されるので、ごみ箱は普通に受け取る。**12.11 にも 12.11a にも代用できない。**
（この確認で出たごみ箱の項目は、元のパスが scratch であることを確かめてから永久削除してある。
`InvokeVerb('元に戻す(&E)')` は何も起こさなかった — ごみ箱に入れたときのドライブ文字 `Z:` が
もう無いせいだと思われる。）

## 所見

### 1. TESTING.md 12.8 の後半（と 12 節の前文）が v0.60.0 で古くなっている

- 12.8 の期待: 「Creating a file records no undo step, so a new file leaves the redo in place (#83)」
- 12 節の前文: 「12.8 used to fork history by creating a file, which records no undo step; it now renames a second file (#83)」

**どちらも #83 当時（`a` が取り消せなかった頃）の話で、v0.60.0 で `a` が `UndoStep::Create` を積むようになってから
成り立たない**（12.17 はその取り消しを確かめる行）。`app.rs:4146` が `Land::Fresh` で積み、`Land::Fresh` は
`redo.clear()` する（`app.rs:1061-1068`）ので、作成も改名と同じく履歴を分岐させる。上の実測がそれ。

**これはプログラムの不具合ではなく、行のほうが古い**と見ている。新しい動作のほうが素直で（新しい操作はすべて
履歴を分岐させる、という 1 つの規則になる）、12.17 の `u` / `U` はその上に成り立っている。

直し方の案（持ち主かマージする側の判断。実機からは TESTING.md を書き換えない）:

- 12.8 の期待を「Redo is gone: the new rename forked history.」で止める。
- 「作成も分岐させる」ことを確かめたいなら、別の行として足す。例:
  `12.8a | ファイルを `r` で改名 → `u` → `a` で別のファイルを作る → `U` | `Nothing to redo`。作成も履歴を分岐させる（v0.60.0 で `a` が取り消せるようになったため。#83 当時は redo が残った）`
  この実行の後半が、そのまま 12.8a の証拠になる。
- 12 節の前文の最後の 1 文も同じ理由で古い。

### Proposals

1. **改名が成功したときにトーストが出ない。**この実行で 3 回改名したが、`r` + `<Enter>` のあと
   `FILER_KEYS_DONE` の `toasts:` は空で、画面にも何も出ない。`d` は `Trashed <名前> — u to undo`、
   `-` は `Linked <名前> — u to undo`、`u` は `Renamed back to <名前>` と言うのに、改名だけが黙っている。
   一覧の行は変わるので気づけるが、**「取り消せる」ことを言う機会がここだけ無い**（v0.57.3 が `d` に
   トーストを足したのと同じ話で、12.13 がその行）。
   **こうするべき**: 改名の成功で `Renamed to <新しい名前> — u to undo` を出す。文言は既にある
   （`UndoStep::redone_label()` の `format!("Renamed to {}", …)`）。
   **大きさ**: 1 行（`do_rename` の `Ok(())` の腕、`app.rs:4162-4165`。今はそこで `undos.land` だけをして
   何も言わない）＋ TESTING.md に 1 行。

2. **`--keys` の起動は `Start-Process -Wait` だと役割定義に書くべき。**`filer.exe` は GUI サブシステムなので、
   PowerShell から `& filer.exe … --keys …` と呼ぶと**キーが押される前に制御が戻る**。この実行の 1 回目は
   それで一覧を早く読んでしまい（`a.txt` / `b.txt` のまま）、続けて起こした 2 回目が同じ
   `FILER_KEYS_DONE` を**黙って上書き**したので、1 回目の `toasts:` が消えた。`windows-role.md` の
   `--keys` の段落は「filer presses keys itself」としか書いておらず、待ち方に触れていない。
   **こうするべき**: 「Start it with `Start-Process -Wait` (filer.exe is a GUI-subsystem binary: `&` returns
   before the first key goes in), and give every run its own `FILER_KEYS_DONE`」の 1 文を足す。
   **大きさ**: 役割定義に 1 文。プログラム側で手を打つなら、`FILER_KEYS_DONE` が既にあるときに
   `<name>.1` を書く案もあるが、黙って上書きしないだけでも値打ちがある。

3. **`cargo build --release` が吐くのは `filer-com.exe` で、リリースの zip の `filer.com` ではない。**
   今回は `target\release` に `filer.com` が既にあった（前の実行が複製したもの）が、きれいなチェックアウトでは
   無いので、`filer env` を PowerShell から待って読めない。

   複製もする（実機のセッションはどのみちこのスクリプトを呼ぶ）。
   **大きさ**: スクリプトに 2 行。
