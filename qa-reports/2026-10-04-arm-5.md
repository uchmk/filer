## Proposals

1. **`--keys` needs a key that quits whatever is open.** What happened: the 5.11 script ended in
   `q`, which in the compare view means *close the view*, so the window stayed up; the launching
   `Start-Process -Wait` (the rule from #225) sat there until the 180 s timeout and the run had to
   `Stop-Process -Name filer`. `q` is "close" in some states and "quit" in others, so a script that
   guesses the state wrong hangs rather than fails. What should change: a `<Quit>` key in the script
   notation (or `FILER_KEYS_QUIT=1`) that ends the process after the last key whatever is on screen,
   writing `quit: yes` as `q` does today. Why: every unattended run drives filer this way, and a
   hang costs minutes and leaves a process behind — the one thing the role file asks us never to do.
   How big: a line in `keyscript.rs` and a branch beside the existing quit path.
2. **The state report should carry the compare view's rows, with the changed ranges marked.**
   `compare:` prints the two paths today; the rows themselves are only pixels. Settling 5.11 took a
   100-line pixel script, two colour samples and four span measurements for what the program already
   knows exactly (`diff::Line::changed`). A line like
   `compare row 2: ~ the ⟦price⟧ is firm | the ⟦cost⟧ is firm` would make the whole of 5.11 — which
   word is marked, that a wholly changed line marks none — readable text, and the picture would then
   be needed only for the colours. Why: the same shape as `pick:` and `confirm:` (#230), which is how
   those rows stopped being pictures. How big: a function in `state_report`.
3. **The file compare's footer should say how many differences there are.** The folder compare's
   footer reads `0 only left · 0 only right · 1 differ · 1 match`; the file compare's reads only
   `1–7 of 7`, so the number of differences can be learnt only by pressing `n` until the toast says
   `At the last difference`. In this run the two views were open a minute apart on the same pair of
   trees and the asymmetry was plain. What should change: append `· N differences` to the file
   view's footer. Why: it is the first thing you want from a diff, and the view already counts the
   blocks for `n` / `N`. How big: a line in `compare_frame`'s footer, and the automated footer test
   grows a field.
4. **`make-fixtures.ps1` should grow the word-level pair.** Section 5's fixtures stop at
   `compare-left/right.txt`, which has no single-word change and no Japanese, so 5.11 cannot be
   pressed from the standard fixtures at all — this run had to write its own files, and the next run
   to take 5.11 will write different ones. What should change: add `compare-words-left.txt` /
   `-right.txt` with the three lines used here (a one-word change, a Japanese word change, a line
   with nothing in common). Why: a checklist row whose fixture is improvised is a row whose result
   cannot be compared between runs. How big: four lines in the script and a line in TESTING.md's
   "What you need".
