### Proposals

#### 提案 1 — `[[mgr.keymap]]` で一覧のキーが全部死んだら、そう言ってほしい（1 関数ぶん）

**何に当たったか。** 36.10 の括弧の半分を押したとき、`keymap.toml` に `[[mgr.keymap]]` で `<S-t>` 1 本だけを
書いた状態で filer を起動すると、**`j` も `T` も `q` も効かない窓**ができた（上の表のとおり、`hovered:` も
`max preview:` も動かない）。画面に出ている手がかりは `` `<S-t>` can never be pressed `` のトースト 1 本だけで、
これは数秒で消える。消えたあとは、キーを受け付けない窓が残り、`q` では閉じられない。

**どう変わるべきか。** keymap を組み立て終わった時点で、`mgr` レイヤに**押せる束縛が 1 本も無い**とき、
今の警告に続けてもう 1 本出す:

```
[[mgr.keymap]] replaces the defaults; no key in the list can be pressed now
  -- did you mean [[mgr.prepend_keymap]]?
```

**なぜ。** `[[mgr.keymap]]`（置き換え）と `[[mgr.prepend_keymap]]`（追加）は 1 語違いで、yazi の設定を
初めて書く人が間違える側がはっきりしている。間違えた結果は「キーを 1 つ足したら、ファイラが全部のキーを
無視するようになった」で、原因の表示が無い。しかも `q` が効かないので、窓を閉じるにはタイトルバーか
タスクマネージャに行くことになる。36.10 はこの状態を**正しい挙動として固定している行**なので、挙動を
変えるのではなく、起きたことを名前で言うのが筋だと思う。

**大きさ。** keymap のマージの直後に 1 か所。`mgr` レイヤの束縛数と、`keys.rs` が「押せない」と判定した数を
比べるだけなので、警告の文面を足す関数 1 つぶん。

#### 提案 2 — `E` の名前の欄で、拡張子を次の形式へ回すキーが欲しい（1 関数ぶん）

**何に当たったか。** 21.14 のために `.zip` / `.tar.gz` / `.7z` の 3 つを作るのに、`E` の欄で
**`<End>` と `<Backspace>` 4 つを打ってから `.tar.gz` と打ち直した**。既定の `to-pack.zip` は語幹が選択された
状態で開くので、素直に `<Backspace>` を押すと**語幹が丸ごと消えて `.zip` が残り**、2 回目以降の
`<Backspace>` は何もしない（測った値: `bs1` も `bs3` も `input: .zip`）。語幹を残して拡張子を変える、という
いちばんよくある操作がいちばん打ちにくい。

**どう変わるべきか。** 名前の欄に、**拡張子だけを `.zip` → `.tar.gz` → `.7z` → `.zip` と回すキー**を 1 つ置く
（`<Tab>` は `complete` に使われているので、`<A-e>` あたり）。語幹は触らない。

**なぜ。** 21.5 と 21.7 が「名前を `.tar.gz` に変える」「`.7z` に変える」と書いているとおり、形式の選択は
**名前の編集として**されている。filer が固められる形式は 3 つに決まっているので、打ち直す理由が無い。
手で使うときも、`to-pack` のような長い名前では「語幹を消さないように `<End>` へ行く」のが毎回の手間になる。

#### 提案 3 — `filer env` のシェルに版を出してほしい（1 行ぶん。ただし 25.4d と相談）

**何に当たったか。** 25.4a で `filer env` が挙げたのは
`pwsh : C:\Program Files\WindowsApps\Microsoft.PowerShell_7.6.6.0_arm64__8wekyb3d8bbwe\pwsh.exe` だった。
一方、ペインを開けたときのトーストは `Started powershell (Windows PowerShell 5.1)` と**版を言っている**。
`git` の行は `git version 2.55.0.windows.5` と版を出しているのに、シェルだけ出ていない。

**どう変わるべきか。** Tools のシェルの行に版を付ける。`git` と同じ形で
`pwsh 7.6.6 : C:\...` か `pwsh : C:\...  (terminal pane, from [term] shell; 7.6.6)`。

**なぜ。** この機械では `pwsh` が WindowsApps のパスで解決するので、**フォルダ名を読まないと版が分からない**。
`powershell` のほうはパスに版が入らない（`v1.0` は常にそう書かれるだけで、実体は 5.1）。「ペインで動くのは
どの PowerShell か」は、ペインの中で何かが動かないときに最初に知りたいことで、いまはペインを開けて
トーストを読むしかない。

**気をつける点。** 25.4d が「`filer env` は `PATH` を引くだけで、プログラムを**実行しない**」を保証している
（画面に何も開かないことの根拠）。だから `pwsh --version` を起動して取るのは**この保証を壊す**。
ファイルのバージョンリソース（`FileVersionInfo`）から読めば実行しないで済むので、そちらで。

**大きさ。** 取得は 1 行。`git` の版は実行して取っているはずなので、「実行しないで版を取る」経路を
1 本作る話になるかもしれない。
