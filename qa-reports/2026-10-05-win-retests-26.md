### Proposals

1. **Help should show the layer the user is in.** `<F1>` does nothing inside the
   picker (or any overlay, as far as `help_lines` goes), and the help panel from the
   list lists only `[mgr]` (plus `[term]`). So the `[pick]` and `[input]` rows the
   keymap now carries -- `<C-n>`/`<C-p>`, `<Tab>` completion -- are visible only in
   TESTING-KEYS.md. Either let `<F1>` open help from an overlay with that overlay's
   layer first, or add the `[pick]` / `[input]` / `[confirm]` layers as sections
   under `[mgr]`. Until then, row 32.18's last clause cannot pass.
2. **`--keys` needs a wait that does not settle.** Every key, `<Wait:N>` and
   `<State:>` waits until no task is queued or running (`App::settled`), and `<Now>`
   is refused unless a key follows it. So "start a job, wait 500 ms, look" cannot be
   written, and stopping a job mid-flight only works as `<A-c><Now>w<Now>x` with no
   look in between. A `<Now>` that may precede `<Wait:>` / `<State:>` (or a
   `<Sleep:N>` that ignores tasks) would let 6.x rows read the running state.
   At the least, `windows-role.md` should say how 6.16 was done.
3. **The state report should list the tasks.** `jobs: 0 running` is the same for a
   finished copy and a stopped one; telling `[cancelled]` from `[done]` took a
   screenshot. A `tasks:` line (`Copy 1 item(s) cancelled 1/3000`) would make 6.16
   and the other task rows text-checkable.
