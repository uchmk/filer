### Proposals

1. **Keep the "no path" note when a `;` line with a shell operator fails.** In k3223a the launch first toasted
   `$ type nothing.txt >t.txt (no path: the line has a shell operator; use %* to place it)`. The failure toast then
   replaced it, and `toasts shown:` has only `Command failed: …`. When such a line fails, the skipped path is the likeliest
   cause the user can fix (`;type %* >t.txt`), and the hint is gone at the moment it would help.
   - Suggest: add `(no path: …)` to the failure toast, or keep the note on screen when the launch fails.
   - Why: a reader sees `指定されたファイルが見つかりません。` and does not learn that filer left the path out.
   - Size: a few lines where `launch` swaps the toast in `app.rs`.
2. **Have `make-testcheck -- --check` compare the `(vX.Y.Z)` tags of the two halves** (finding 2). A checker that says
   `in sync` while the translation names another version leaves the drift for a person to see by eye. This run noticed
   it only because the row was read in full. Size: a function in the example.
3. **Gate the stale-tick case of Q89 in one place.** Finding 1 makes three rows with one cause: 32.10, 32.21 and 32.23's
   middle clause. Suggest that the Q89 TODO item list all three rows to re-test, so the fix puts them back together.
   Size: a TODO.md line.
