### Proposals（3 件）

#### 提案 1: `FILER_KEYS_DONE` に `scale:` の行を足す

- **踏んだこと**: 倍率 150% にしてから測ったが、状態ファイルには倍率の行が無く、`toasts:` の履歴（`Scale 110% | … | Scale 150%`）で確かめるしかなかった。トーストが消えた後の run（または `<C-=>` を押し損ねた run）では、倍率が分からない。
- **どう変えるべきか**: `state_report` に `scale: 150% (ppp 1.50)` のような 1 行を足す。filer の `scale` と、egui の `pixels_per_point`（OS の倍率込み）の両方。
- **なぜ**: 倍率に依る行（3.2、4.9、3.1 の `fit N%`、ペインの大きさ）は、どの倍率で測ったかが根拠の半分になる。今は絵から逆算するしかない。
- **大きさ**: `src/main.rs` の `state_report` に 1 行。

#### 提案 2: `util::test_dir` のフォルダを、テストの終わりか次の run の始めに片付ける

- **踏んだこと**: この run の `cargo test` 1 回で、`TEMP` に `filer-<label>-<test>-<pid>` が 248 個残った。名前に pid が入るので、次の run の `remove_dir_all` は前の run のものを消さない。持ち主の `%LOCALAPPDATA%\Temp` には 1414 個（12 回分）溜まっている。
  一覧の親の列もこれで埋まり、名前はどれも `filer…84` に縮んで見分けがつかなかった（`out\p150\one.png`）。
- **どう変えるべきか**: どちらか。(a) テストが成功したら消す（`Drop` で消すガードを返す）。(b) `test_dir` の初回に、pid が生きていない `filer-*-<pid>` を消す。
- **なぜ**: RAM ディスクなら電源で消えるが、C: の `TEMP` では run のたびに増え続ける（1 回 6 MB、2000 ファイル）。
- **大きさ**: `src/util.rs` の 1 関数と、それを確かめるテスト。

#### 提案 3: 一覧の名前を縮めるとき、同じ列で同じ見た目になるなら残す部分を増やす

- **踏んだこと**: 親の列（幅は約 150 px）で、`filer-archive-fs-archive-tests-…-15484` などが全部 `filer…84` になり、17 行がまったく同じ文字列に見えた。
- **どう変えるべきか**: 縮めた結果が隣の行と同じなら、末尾の側を `-15484` のような区切りまで残す、あるいは頭を長く残す（`filer-archive…84`）。
- **なぜ**: 同じに見える行が並ぶと、どれにカーソルがあるかが分からない。長い名前が並ぶフォルダ（ログ、ビルドの出力）でよく起きる。
- **大きさ**: 名前を縮める関数 1 つ。見た目の判断が入るので、文字の残し方は持ち主向け。
