### Proposals

3 件。

#### 1. `last-run.toml` に、そのとき効いていた `[ui] backend` も残す

- **何に当たったか**: 所見 1。`filer env` が `Backend : [ui] backend = "auto"` と `Adapter : …(Vulkan, …)` を**並べて**出すので、
  「auto は Vulkan のことだ」と読める。実際は前の run（`"metal"` を書いた #244）の記録で、既定の窓は GL で開いていた。
- **何を変えるか**: `runinfo` に `backend_setting`（その run で効いていた `[ui] backend`、`WGPU_BACKEND` があればそちら）を足し、
  `Adapter` の行に `… (Gl, Other)  [backend = "auto"]` のように添える。時刻（#244 の提案 3）と合わせれば
  「いつの、どの設定の記録か」が 1 行で分かる。
- **なぜ**: `Adapter` は「白い窓・遅い窓」の唯一の文字の出口で、`filer env` 以外に読む所が無い。
  記録が**いつのものか・どの設定のものか**が書いていないと、設定を切り替えて試した直後が一番誤読しやすい。
  2 つのレーンが `[ui] backend` の調査で 4 本連続 PR を使っている最中なので、今が一番効く。
- **大きさ**: フィールド 1 つと表示 1 行。

#### 2. 無い名前へ飛んだとき、カーソルを**一番近い既存の名前**に置く

- **何に当たったか**: 23.6 の `tpyo` の run。`<S>\s23fresh\tpyo` を開くと `s23fresh` が出るが、
  `hovered:` は一覧の先頭（`sub`）。`nosuch-abc123` の 8 回も全部先頭だった。
- **何を変えるか**: 飛び先の葉が無かったときは、その葉と**同じ前方一致（なければ最長共通前置）**の行にカーソルを置く。
  行の名前がまさに `tpyo`（`typo` の打ち間違い）なので、`a.tx` → `a.txt`、`su` → `sub` のような打ち損ないが
  「エラーを読む → 目で探す → `j` を何度か」ではなく、着いた時点で当たりに乗っている。
- **なぜ**: 23.6 は「打ち間違い」の行で、filer はもう親を開くところまでやってくれている。
  あと 1 歩が無いので、結局ユーザーが一覧を目で走る。ファイル名を途中まで打って飛ぶのは `g<Space>` の普通の使い方。
  ファイル名のときは既にその挙動（`b.txt` に乗る）なので、**無い名前のときだけ先頭に落ちるのが不揃い**でもある。
- **大きさ**: 関数 1 つ（`arrive` で `reveal` を解決するところに、完全一致が無いときの前方一致を足す）。

#### 3. `filer env` の `Backend` の行に、`auto` が**この機械で何になるか**を書く

- **何に当たったか**: 同じく所見 1。`Backend : [ui] backend = "auto"` だけでは、v0.75.0 で Windows の `auto` が GL に
  なったことを知らないと読めない。CHANGELOG を読んでから窓を 1 つ開けて `Adapter` を読み直す、という手順を踏んだ。
- **何を変えるか**: `[ui] backend = "auto" (gl on Windows since v0.75.0; vulkan/dx12 if no GL)` のように、
  解決先を同じ行に 1 つ。`"vulkan"` のように明示されているときは今のままでよい。
- **なぜ**: 既定が変わった直後は、`filer env` を読む理由がまさに「既定が何か」。
  いま一番知りたい 1 語だけが書いていない。
- **大きさ**: 1 行。
