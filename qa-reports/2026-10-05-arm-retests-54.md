### Proposals

1. **Start the `<S-Enter>` chooser's cursor on the first opener that is installed.**
   What I ran into: with the missing opener first in `[opener]`, `<S-Enter>` put the cursor on
   `Missing tool (not found)` (`picked: Missing tool (not found)` in `pick.txt`), and `<Enter>` ran it into
   `Open failed: \`no-such-tool\` was not found`. The chooser already knows it is missing — it says so on that
   very line. What should change: the initial cursor skips entries marked `(not found)` (falling back to 0 if all are).
   Why: `<S-Enter><Enter>` is the habit for "open with the usual"; a stale entry at the top of a shared `yazi.toml`
   (one machine has the tool, this one does not) turns that habit into an error every time. Size: a few lines where `PickOverlay.cursor` is set.
2. **Keep the label and the command apart in the `pick:` state line.** What I ran into:
   `Missing tool (not found) (no-such-tool %s)` — two parenthesised groups in a row, so a script reading
   `<State:>` cannot tell where the label ends without knowing the command; a `desc` that itself ends in `)`
   makes it worse. What should change: `pick:` lists the labels only (as `picked:` already does), and a new
   `pick runs:` line lists the commands in the same order. Why: the state lines are what runs like this one
   read instead of pictures; an unambiguous split costs nothing. Size: a line in `main.rs` and its test.
3. **The ARM64 table's (2) still reads as blocked after its condition was met.** The hook landed in v0.78.54; on
   v0.78.110 the row still says "skip this until … lands" (#261, #263 and #264 skipped it rightly, before v0.78.54,
   citing the TODO item by line number). A run that reads the row and not TODO.md skips it again. What should change: when a TODO item a queue row waits on is ticked, the merger edits that
   row in the same step (`merge-role.md`, alongside "add x64's new ticks"). Size: a sentence in `merge-role.md`.
