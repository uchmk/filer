## Findings

1. **32.23's second sentence no longer holds on a Japanese Windows** (v0.78.121). `;nosuchprog-xyz` (r6 above) and an
   `[opener]` line naming `no-such-tool` (the Q87 run below) both toast `cmd`'s own Japanese "not recognized" sentence,
   never `` `nosuchprog-xyz` was not found ``. Cause: `Launch::watch` (`src/exec.rs:338`) uses `stderr_text` first and
   only falls back to `missing_program` when stderr is empty; since v0.78.116 decodes CP932, `cmd`'s stderr is never
   empty here, so the named sentence is unreachable for a `cmd` line on this machine (and on an English Windows,
   whose stderr was always valid UTF-8, it likely never showed either). Either the row's last sentence should say
   "`cmd`'s own sentence naming `nosuchprog-xyz`", or exit 9009 with a missing program should prefer the named
   sentence (proposal 1). TODO.md's Q87 item also quotes the old ``Open failed: `no-such-tool` was not found``.

## Proposals

1. **A missing program should be named, not explained by `cmd`.** What I ran into: r6 and the Q87 run -- the toast is
   `Open failed: 'no-such-tool' は、内部コマンドまたは外部コマンド、 操作可能なプログラムまたはバッチ ファイルとして認識されていません。 — no-such-tool "R:\…\a.txt"`,
   which wraps over three lines of the state file and pushes the command off the toast. What should change: when the
   exit code is 9009 (or 127) and `missing_program` finds the program absent, say `` `no-such-tool` was not found ``
   (the same words as `(not found)` in the `<S-Enter>` list), and keep `cmd`'s stderr for every other failure, where it
   is the only explanation (r5's `指定されたファイルが見つかりません。`). Why: the short sentence is what 32.23 and the Q87
   background both expect, and it reads the same on any Windows language. Size: a few lines in `Launch::watch`.
2. **A failed line's toast repeats the whole command.** What I ran into: r5 / r6 -- `toasts:` holds `$ nosuchprog-xyz "R:\…\a.txt"`
   and then `Open failed: … — nosuchprog-xyz "R:\…\a.txt"`, the same path twice within a second. What should change:
   drop the `— <cmdline>` tail when the `$ …` toast for the same launch is still showing (or replace that toast instead
   of adding a second). Why: on a long path the failure's own words are what gets cut. Size: a function.
