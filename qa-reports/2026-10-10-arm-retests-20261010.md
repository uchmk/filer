## 所見

1. **TESTING.md 49.10 の後半が pwsh では成り立たない。** 「`<S-Enter>` runs the line as before」は PSReadLine の既定（Shift+Enter = AddLine）と合わない。
   旧ビルドも同じなので退行ではない。行を「`claude` の入力欄では 2 行になる。pwsh では AddLine のまま（行は走らない）」に直すか、`Set-PSReadLineKeyHandler -Key Shift+Enter -Function AcceptLine` を入れた pwsh と書く。
2. **`wezterm imgcat` が 2560x1280 の PNG で何も出さない**（160x80 は出る）。`CSI 16 t` の答えは返っているので、大きな絵の iTerm2 インラインの受け取り（サイズ上限か、OSC 1337 の長さ）の可能性。tsumugi 側の調べ。
3. **TESTING.md 1.43 と 40.16 の `<C-c>` の書き方が古い。** v0.86.0 から `<C-c>` は `in key    \x03`（名前無し）で届く。`(Ctrl+c)` を探す行は、`(Ctrl+Left)` など別のキーに換える。
4. `osc.ps1` で `\e]11;?` / `\e]10;?` を出したあと、シェルが読んでいないうちに返事（`\e]10;rgb:…\e\\`）が pwsh の入力に入り、次に打った `ping` の前に `\` が付いた。
   普通の端末も同じ（読み手の無い返事は入力になる）なので退行ではないが、1.41 を押す人は返事のあとに `<Enter>` かスクリプト内の `Start-Sleep` で受けるとよい。

### Proposals

1. **TESTING.md の 49.10 を分ける。** 前半（kitty のキー拡張を求める `claude` で `<S-Enter>` が 2 行）と、後半（kitty を求めないシェルでは `<S-Enter>` が変わらない）に。後半は `pwsh` でなく `cmd` か `bash` で測る。
2. **1.43 / 40.16 の `<C-c>` を 49.9 に寄せる。** `<C-c>` の `in key` 行の書き方は 49.9 が持っている（`\x03`）。1.43 は `(Alt+b)` と `(Up)` だけにする。
3. **`scripts\keys.ps1` に `<Wheel:N>` と `<Drag:…>` の例を README のキー表に書く。** 今回、ホイール・ドラッグの行には手が回らなかった。次の run がすぐ書けるように。
