### 47.6 — この機械の `gl` は GLon12 だが、ちゃんと描く

ARM64 の順番表の問い（「`gl` でアダプタが取れるのか、取れずに既定へ戻るのか」）の答えは**取れる**。
ただし名前が紛らわしい:

```text
Adapter       : D3D12 (Qualcomm(R) Adreno(TM) X2-90 GPU)   (Gl, Other)
```

`backend = "Gl"` だが、アダプタ名は `D3D12 (…)`、種類は `IntegratedGpu` ではなく `Other`。
Windows on ARM の OpenGL が D3D12 の上の変換層（GLon12 / Mesa）で出ているためで、**警告は出ない**
（`filer env` の `Warnings : none`、`toasts:` も空）。描画も生きていて、`--keys "j<Shot:gl-window>…"` の
`gl-window.png` は一覧・アイコン・色・プレビューまで普通に出ている（`hovered:` が `bulk-rename` に動き、
`preview top: 0 of 14` もある）。つまりこの機械では `gl` は**選べて、使える**。

47.1 の半分は、既定（Vulkan）でも `gl` でも 10 秒で 0.000 s。x64（AMD）のように 1 コアを使う現象は
**この機械では既定でも起きない**（#232 の x64 は Vulkan / DX12 で 10.0 s）。

### Proposals（3）

1. **`filer env` に `[ui] backend` の検査と、設定された値を出す。**
   - 何があったか: `backend = "directx"` の設定で `filer env` が `Warnings : none`。窓を開けば
     トーストが出るのに、診断では読めない（`env-dx.txt` と `dx.done`）。この run では、どの設定で
     どう落ちたかを知るのに毎回 GUI を起動して `toasts:` を読む必要があった。
   - 変えるもの: `envreport` で `cfg.ui.backend_name()` を呼び、`Err` なら `Warnings` に足す。
     ついでに「Last run」の `Adapter` の隣に、設定の値（`[ui] backend = "gl"` か `auto`）を 1 行出す。
     「この機械にアダプタが無い」側は wgpu を起こすので `filer env` では無理だが、名前の誤りは純粋に設定の検査で分かる。
   - なぜ: 設定の打ち間違いは `filer env` で見つかるべきで、今は「窓を開いてトーストを読む」しか道が無い。
   - 大きさ: 数行（`backend_name()` は既にある）。
2. **README の `backend` の段落に、Windows の `gl` が変換層で来ることを 1 行足す。**
   - 何があったか: この機械の `gl` は `D3D12 (Qualcomm(R) Adreno(TM) X2-90 GPU) (Gl, Other)` と名乗る。
     `Gl` なのに名前が `D3D12` で、種類が `IntegratedGpu` から `Other` に落ちる。

   - なぜ: 47.6 のような行や、人からのバグ報告の `Rendering:` を読むときに、毎回この疑問で止まる。
