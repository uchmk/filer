### 見つけたこと

1. **何もしていない窓が、CPU を 1 コア使い続けている（47 節の後退、x64）。**
   - 0.73.26 を起動して何もしないと、10 秒で約 10 CPU 秒を使う。持ち主の設定でも run 用の設定でも同じ。前面でも背面でも、最小化しても同じ。`--keys` の有無にも依らない。
   - バックエンドで分けると:

     | `WGPU_BACKEND` | アダプタ（`filer env`） | 10 秒の CPU |
     | --- | --- | --- |
     | 無し（既定） | RX 9070 XT（Vulkan） | 約 10 s |
     | `dx12` | Dx12 | 9.84 s |
     | `gl` | Gl | 0 s |

   - 忙しいのは UI のスレッドではない 1 本のスレッドで、10 秒で 10 秒を使う（UI のスレッドはほぼ 0。filer が描き直し続けているのではない）。
     `NtQueryInformationThread` でそのスレッドの開始アドレスを取ると、**Vulkan では `amdvlk64.dll`（AMD の Vulkan ドライバ 9.2.10.395）の中、
     DX12 では `amdxc64.dll`（8.18.10.0504）の中**だった。どちらも AMD のドライバが作ったスレッド。
   - これまでの x64 の 47.1 の印は 0 CPU-s で付いている（QA-REPORT.md の以前の run）ので、どこかで変わった。ドライバ（2026-08-17 付）の更新以後に起きている公算が高いが、
     filer のスワップチェーンの使い方（present mode など）がドライバの忙しい待ちを引き起こしている可能性も残る。この run では切り分けていない。
   - 47.1 の `[x]` は、この機械では今は成り立たない。印を外すかどうかはマージする側に任せる（「提案 1」）。
2. **（手順の注意）`Start-Process` に `"C:\"` を渡すと、引数が潰れる。**`\"` が引用符のエスケープと読まれ、パスと後ろの `--keys` が 1 つの引数になる。
   filer はそれを 1 つのパスとして受け、`Filer: R:` のような窓が開き、`<Shot>` も `FILER_KEYS_DONE` も書かれない。filer の不具合ではない（Windows の引数の規則）が、
   14.6 のようにドライブ直下で起動する行を回すと必ず踏む。`'C:\\'` のように末尾の `\` を二重にすると通る。

### Proposals（3 件）

#### 提案 1: 47 節を x64 で測り直し、GPU のバックエンドを選べるようにする

- **踏んだこと**: 「見つけたこと 1」。何もしていない窓が 1 コアを使い続け、その出どころは AMD の Vulkan / DX12 ドライバのスレッドだった。GL なら 0。
- **どう変えるべきか**:
  1. 47 節を順番表に戻し、x64 で測り直す（`Re-tests` に 47.1 / 47.4）。ARM64 でも同じかを見る。
  2. `filer.toml` か環境変数で wgpu のバックエンドを選べることを README に書く（`WGPU_BACKEND` は今でも効く）。あるいは、
     present mode を `AutoVsync` / `Fifo` に固定して変わるかを試す（ドライバの忙しい待ちが mailbox / immediate 系の present で起きることがある）。
  3. 持ち主の機械なら、AMD のドライバを更新して変わるかを見る（【人】）。
- **なぜ**: ノート PC なら電池に直に効く。47 節の印が付いたまま、実機では成り立っていない。
- **大きさ**: 1 は順番表の 1 行。2 は README の数行か、`NativeOptions` の 1 行と実機での測定。

#### 提案 2: `--keys` の途中で状態ファイルを書けるようにする（例 `<State:name>`）

- **踏んだこと**: `FILER_KEYS_DONE` は最後に 1 回しか書かれないので、「クリックの前」と「後」の状態を読むために、形ごとに filer を起こし直した（14 節の測定だけで 13 回）。
  #202（19 節）の提案 3 と同じ。
- **どう変えるべきか**: `<Shot:name>` と同じ形で、その時点の状態を `<FILER_KEYS_DONE の名前>.<name>` に書く `<State:name>` を足す。
- **なぜ**: 前後の値を同じ起動で読めれば、マウスのように `--keys` の外から入れる操作の行が、半分の起動で済み、起動ごとの揺れも入らない。
- **大きさ**: `state_report` を呼ぶ所を 1 つ足す程度。

#### 提案 3: 役割定義か TESTING.md の冒頭に、ドライブ直下の引数の書き方を 1 行書く

- **踏んだこと**: 「見つけたこと 2」。最初の 14.6 の起動は、窓は開くのに何も書かれず、原因を探すのに 1 回分を使った。
- **どう変えるべきか**: `windows-role.md` の起動の例の近くに「ドライブ直下は `'C:\\'`（末尾の `\` を二重に）で渡す」と書く。
- **なぜ**: 無人の run は誰も窓を見ていないので、「起動したが何も書かれない」は時間切れまで気づけない。
- **大きさ**: 1 行。
