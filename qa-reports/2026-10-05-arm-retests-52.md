## Proposals

### proposal 1 — picker（`O` / `<S-Enter>` / パレット）で `j` / `k` も動かす、せめて動かし方を出す

**何があったか**: 37.8a で一覧の 3 番目を選ぼうとして `O` のあと `jj` を押したら、
トーストが `Nothing matches \`jj\` — <Esc> closes` になった。`j` は絞り込みの文字として入っていた。
動かすには `<Down>` が要る（`[pick]` の keymap には `<Enter>` と `<Esc>` しか無い）。

**どう変えるか**: `[pick]` の層に `<C-n>` / `<C-p>`（と `<C-j>` / `<C-k>`）を「1 行動く」として足す。
`j` / `k` そのものは絞り込みに要るので取らない。あわせて picker の足に `<Down>/<Up> move · Enter open · Esc cancel` のような
1 行を出す。

**なぜ**: filer の一覧・ヘルプ・spot・比較・タスクはすべて `j` / `k` で動く。picker だけが違い、しかも**画面に何も書いていない**
ので、間違えたときに初めて分かる。fzf や yazi の絞り込みに慣れた人なら `<C-n>` を先に試すはずで、それが効けば事故にならない。

**大きさ**: keymap の 2〜4 項目と、オーバーレイの 1 行。設計の選択は「`j` を絞り込みのままにするか」だけ。

### proposal 2 — `start ""` の既定アプリが何も開かなかったとき、そう言う

**何があったか**: 37.8a の 3 番目で、filer は `$ start "" "…\doc.pdf"` とトーストを出し、`filer env` の `Launched` にも残した。
**それでも何も起きない。**画面上は成功と区別が付かない。原因はこの機械の `.pdf` の関連付けが半分壊れていることだが
（finding 3）、filer の側から見えるのは「`cmd` が 0 で返った」だけ。

**どう変えるか**: `start ""` 系のオープナーに限り、起動の前に `AssocQueryStringW(ASSOCSTR_EXECUTABLE)` で
その拡張子にハンドラがあるかを引き、無ければ
`No app is associated with .pdf — <S-Enter> to pick one` のような赤いトーストにして**走らせない**。
`assoc` / `ftype` と違って `AssocQueryString` はシェルと同じ解決をするので、`UserChoice` だけを読むより当てになる
（finding 3 がその反例）。

**なぜ**: 「押したのに何も起きない」は、filer が悪いのかファイルが悪いのか機械が悪いのか分からない唯一の失敗の形で、
報告しようもない。拡張子の関連付けが壊れるのは Windows ではよくある。

**大きさ**: Windows だけの関数ひとつと、`exec.rs` の分岐 1 か所。

### proposal 3 — 自分の `filer-archive-<pid>` は、きれいに終わるときに消す

**何があったか**: この run の scratch に `filer-archive-<pid>` が 6 個残った（finding 4）。
`sweep_archive_scratch` は他プロセスの 1 日以上前のものしか消さない設計で、自分の分は残る。

**どう変えるか**: `q` / `<Quit>` で終わるときに、**開いた写しを渡したプログラムがもう無ければ**自分の
`archive_scratch()` を消す。判断が難しければ、せめて `preview\` の下だけは必ず消す（21.21 は既にそうなっている）。

**なぜ**: 書庫の中を覗くたびに `%TEMP%` にフォルダが 1 つ増え、1 日消えない。
中身は書庫から出した実体なので、容量としても無視できない（大きな書庫のメンバーを開けばそのまま残る）。

**大きさ**: 終了処理の数行。「開いた写しがまだ使われているか」を見るなら設計の相談（今のコメントは
「`l` で開いた写しはまだエディタの中かもしれない」と書いていて、それが 1 日待つ理由になっている）。
