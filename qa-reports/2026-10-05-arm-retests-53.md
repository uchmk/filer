## 見つけたこと

1. **日本語の Windows で、`:` / `;` の行の失敗が「`type` was not found」と出る（プログラムのせいにする）。**
   `;type<Space>nothing.txt<Space>>t3.txt<Enter>` → `toast: Open failed: `type` was not found — type nothing.txt >t3.txt`。
   `;dir<Space>/b<Space>nothing.txt<Space>>t4.txt` も `` `dir` was not found ``。`type` も `dir` も `cmd` の内部コマンドで、実際に無いのは
   `nothing.txt` のほう（`cmd /d /c "type nothing.txt"` は `The system cannot find the file specified.`、終了コード 1）。
   さらに `;type<Space>a.txt;nothing<Space>>t.txt` は `t.txt` に `A` を書いた（**動いた**）のに、同じ「`type` was not found」が出た。
   原因はコードから読める: `src/exec.rs` の `stderr_text` は標準エラーが UTF-8 でなければ `None` を返し（この機械の `cmd` は CP932 で答える）、
   次の `missing_program` は `BUILTIN` の 6 語（`start` `call` `echo` `cd` `set` `exec`）に無く `PATH` にも無い先頭の語を「無い」と言う。
   英語の Windows なら標準エラーが ASCII なので本当の文が出るはずで、**日本語の Windows でだけ嘘になる**。v0.78.101 が外部プレビューで
   した OEM コードページでの読み取りを、ここにも当てるべき（17.12 と同じ直し方）。`BUILTIN` も `type` `dir` `copy` `del` `move` `ren` `mkdir` などが足りない。
2. **17.12 のエラーが 1 行目で切れて、何が悪いかを言わない。**`'pdftoppm' は、内部コマンドまたは外部コマンド、` で終わる。
   `cmd` の文は 2 行で、「認識されていません」は 2 行目にある。英語でも `…internal or external command,` で切れるはず。行の期待（ツール名、読める、固まらない）は満たすので `[x]` にした。
3. （小さい）壊れたジャンクションの spot で `Preview Error access denied, os error 5` と出る。リンクの節は正しく `not found, os error 2`。
   プレビューの側だけ「権限が無い」と読めるので、壊れたリンクなら `Resolves` と同じ言い方に寄せたほうがよい。
